# Boaz 内存马绕过分析与策略

## 1. 问题分析

用户使用以下命令生成了一个加载Mimikatz的程序：
`python3 Boaz.py -f /Virus/mimikatz_raw.exe -o /boaz/output/boaz_mi_1_easy.exe -t donut -l 1 -c mingw -e uuid`

该程序在虚拟机中运行时，被杀毒软件通过内存扫描检测为 `MEM:Trojan.Win64.Shellcode.a`。

关键信息：
- **`MEM:`**：表明这是内存查杀，AV在程序运行时扫描了其进程内存，而不是静态扫描磁盘上的文件。
- **`Shellcode.a`**：表明AV识别出了内存中一段可执行的、具有攻击性的Shellcode。

这说明我们原始命令生成的程序，在将Mimikatz的Shellcode解密并加载到内存后，其内存特征或行为被AV精准捕获。

## 2. 可能的检测点

根据使用的命令和`README.md`的功能说明，AV可能的检测点如下：

1.  **Shellcode本身**：`donut`生成的Mimikatz shellcode在通过`uuid`解码后，其原始形态暴露在内存中，被AV的特征库命中。`uuid`编码太简单，AV可以轻易在沙箱中模拟解码过程。
2.  **加载器行为**：你使用的 `-l 1`（Loader 1）虽然使用了代理系统调用等技术，但其作为基础加载器，分配内存（如`VirtualAlloc`）、写入内存（如`WriteProcessMemory`）、执行内存（如`CreateThread`）这一系列行为组合可能已经成为一个固定的“行为指纹”，被AV监控。
3.  **缺少深度混淆**：使用 `-c mingw` 进行编译，导致生成的加载器（Loader）本身是未混淆的。AV很容易通过静态分析逆向出加载器的逻辑，从而预测其恶意行为。
4.  **缺少反制措施**：命令中没有启用反-ETW、反-API Hook、反模拟器等功能，使得AV的监控探针可以畅通无阻地工作。

## 3. 绕过策略与建议

为了绕过内存查杀，核心思想是 **让内存中的Shellcode“看起来不像Shellcode”，让加载器的行为“看起来不像加载器”**。我们需要组合使用Boaz的多种高级功能，构建多层防护。

### 策略一：强化Shellcode加密与转换

- **目标**：隐藏Shellcode的原始特征。
- **方法**：
    - 放弃简单的`-e uuid`，改用更强的加密算法，如 `-e aes` 或 `-e chacha`。
    - 尝试不同的Shellcode生成器，如 `-t amber` 或 `-t shoggoth`，它们会产生与`donut`结构不同的PIC（位置无关代码）。

### 策略二：选择更高级、更隐蔽的加载器

- **目标**：改变内存分配、写入和执行的方式，规避行为监控。
- **方法**：从`README.md`的列表中选择一个高级加载器。编号靠后、描述复杂的通常更强。
    - **`-l 37`**: `Stealth new loader (Advanced, evade memory scan)` - 明确为规避内存扫描设计。
    - **`-l 61`**: `Use Page guard to trigger first exception ... no registers and stack pointer and instruction pointer changed in VEH.` - 使用硬件断点和异常处理来执行代码，行为非常隐蔽。
    - **`-l 73`**: `VT Pointer threadless process injection ... Memory guard available with RC4 entryption and PAGE_NOACCESS.` - 使用虚表指针和无线程注入技术，同样非常高级。

### 策略三：启用编译器级混淆

- **目标**：从根本上改变加载器二进制文件的结构，对抗静态分析。
- **方法**：
    - 将 `-c mingw` 更换为 `-c akira` 或 `-c pluto`。
    - 配合 `-mllvm` 参数使用特定的混淆遍（Pass），例如控制流平坦化(`-mllvm -fla`)或指令替换(`-mllvm -sub`)。

### 策略四：组合多种逃逸技术

- **目标**：干扰AV的监控探针。
- **方法**：在命令中添加以下标志：
    - `-etw`：修补ETW，阻止其报告敏感事件。
    - `-u` 或 `-g`：进行API脱钩，确保我们调用的API是“干净”的。
    - `--syswhisper` (`-w`)：使用直接系统调用，绕过应用层的API监控。
    - `-dream`：使用加密睡眠，对抗沙箱和模拟器。
    - `-a`：启用反模拟/反调试检查。

## 4. 建议的命令

综合以上策略，我为你构造了一个新的、强度高得多的命令。你可以从这个例子开始尝试：

```bash
python3 Boaz.py -f /Virus/mimikatz_raw.exe -o /boaz/output/boaz_mi_2_hard.exe \
-t donut -e aes \
-l 37 \
-c akira -mllvm -fla \
-etw -w -a -dream
```

### 命令解析：

- `-t donut -e aes`: 仍然使用Donut，但将编码升级为AES加密。
- `-l 37`: 使用专为内存扫描逃逸设计的第37号高级加载器。
- `-c akira -mllvm -fla`: 使用Akira编译器进行深度混淆，并额外启用控制流平坦化。
- `-etw -w -a -dream`: 同时启用ETW绕过、直接系统调用、反模拟和加密睡眠，构建多层防御。

使用这条命令生成新的 `boaz_mi_2_hard.exe`，然后再次进行测试。如果仍然被检测，可以尝试更换加载器（如 `-l 61`）、Shellcode生成器（如 `-t amber`）或添加更多混淆选项。规避是一个不断试探和迭代的过程。
